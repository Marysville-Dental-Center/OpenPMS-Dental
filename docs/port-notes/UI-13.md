# Port note: UI-13 (every element type in the new look)

Why: the owner's review of gallery G-UI3-ui12p (2026-11-22, `UI-12-owner-review-2.tsv`): four Change rows ("Modernize horizontal sliding
bar" on ControlChart, "Time pattern on the left looks odd" on FormProcCodeEdit, "Scrolling still using old style" on FormProvEdit, "Check
spacing top left. Scrolling bar style is old" on ControlAccount) and "Overall make sure you modernize all element types." Restyle only, in
shared code, plus the layout fixes the four rows need: no behaviour, text, name, event or tab order changes. The UI-12 grid rules, the
owner's standard and the owner's addition (UI-12.md) still hold.

## 1. The look per element type

Every look is in the UiTheme tokens (`CodeBase/UI/UiTheme.Colors.cs`), scales with dpi and zoom, and is attached in shared code: FormODBase and
LayoutManagerForms call `UiInputFrame.AttachTree`/`AttachOne`, which now also calls `UiLooks.AttachOne` (OpenPmsDental/UI/UiLooks.cs). The
painted looks are NativeWindows that let Windows do everything (hit tests, keys, drags, values, events) and paint the look over Windows'
picture in the same message, from Windows' own geometry, so what is drawn is where Windows hits.

## 2. The inventory

`tools/UiFit/element_inventory.py` (no packages) lists every element type: every class the designer files create and the code creates with
`new` (stock Windows Forms types and the program's own) in OpenPmsDental, OpenPmsDentalBusiness, CodeBase and SparksToothChart, the owner-drawn
parts of the program's controls, and the WPF controls of the WPF windows, with their uses. It writes `docs/port-notes/UI-13-inventory.tsv`
(type, drawn, designer, code, styled, by, coverage, fix or reason); `--check` compares. 169 rows: 125 in the new look (styled yes), 27 that
keep Windows' own look or are content (keeps, each with its reason), 17 that draw nothing (n/a: components, layout containers, composite user
controls). `ElementInventoryTests` checks that every row has its code and coverage row or a reason, that every coverage row named exists, and
recounts the designer uses with the tool's rule (a new type in a designer file fails until it is in the inventory).

## 4. What could not change, and why

- Windows' own dialogs and message boxes (file, folder, colour, font, print dialogs, MessageBox): section 1 of the plan keeps the Windows look.
- The stock month calendar (33 uses) and the date picker's drop-down calendar: Windows draws the days, header and hot tracking inside one
  window with no owner drawing; with Windows 11's theme it is the themed calendar, without one the token colours. Swapping the 33 stock
  calendars for the program's MonthCalendarOD would change their events and selection ranges (a behaviour change).
- The stock ToolTip component (24 uses) and ErrorProvider: components, not controls (no window to attach a look to); Windows 11 draws its
  themed tooltip.
- The stock combo box's drop-down list (the list window Windows opens under a stock ComboBox): a separate Windows window the combo box owns;
  its scroll bar is Windows'. The program's own ComboBox (553 uses) draws its own list.
- Content: the tooth chart, the perio chart, sheets and their combo boxes, reports, the print previews' pages, web views, the appointment book's
  content (UQ-8), schedule graphs.
- The gallery harness draws without Windows' visual styles (the test process never calls EnableVisualStyles, as before): Windows' parts the
  looks leave to Windows (the tree and list views' items, the stock list box's items, the month calendar) show their classic picture in the
  gallery and Windows 11's themed one in the program.
