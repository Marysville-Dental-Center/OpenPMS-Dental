## 1. Why

`ProcessStartInfo.UseShellExecute` is `true` by default on .NET Framework and `false` on .NET
(https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.useshellexecute). With `false` a start goes through
`CreateProcess`, which opens no document, folder or URL (only an executable) and refuses a program whose manifest asks for elevation or for UI
access (`ERROR_ELEVATION_REQUIRED`); only `ShellExecute` asks for consent
(https://learn.microsoft.com/windows/security/application-security/application-control/user-account-control/architecture). So every
start that does not redirect a standard stream sets `UseShellExecute=true` explicitly, today's value: **nothing changes on net48**. The starts
that redirect a stream already set `false` and stay as they are.

### 7.3 Item 3: the starters

`ODFileUtils.FuncStartProcessInfo` and `FuncStartProcess` were public mutable static fields. They are now
`internal static Func<...> { get; private set; }`: code outside CodeBase and its friend assemblies cannot see them, and nothing outside
`ODFileUtils` can assign them. The one way to replace them is `internal static StartersReplacement ReplaceStartersForTests(funcInfo,funcProcess)`:
it waits on a process-wide `SemaphoreSlim` (two minutes at most, then `TimeoutException`), puts the recorders in place, and returns a
`StartersReplacement` whose `Dispose` puts back the starters it replaced (kept in `FuncStartProcessInfoReplaced`/`FuncStartProcessReplaced`)
and only then releases the semaphore; a second `Dispose` does nothing. So tests in any class, assembly or thread run one replacement at
a time and never put back another test's recorder, which the class-local lock of `ODFileUtilsStartTests` did not ensure. Replacements are not
nested (a second call waits for the first). `CodeBase/Properties/AssemblyInfo.cs` gains one line,
`[assembly: InternalsVisibleTo("MiddleTierMockTests")]`. A test assembly that wants to record starts later adds its own line.

`tests/MiddleTierMockTests/ODFileUtilsStartTests.cs`: `RunRecorded` uses `using(ODFileUtils.ReplaceStartersForTests(...))` and still asserts
the recorders are in place before the call; the class-local lock is gone. `Starters_DefaultToTheRealStart` reads the defaults as the
starters a replacement replaced (so no other test's recorder can be in place meanwhile). New: `Starters_AreNotPublic_AndSetOnlyByTheScopedReplacement`
(reflection: no field, no public property, internal getter, private setter, internal replacement method),
`ReplaceStarters_Dispose_PutsTheReplacedStartersBack` (put-back, a doubled `Dispose`, and a replacement on another thread that waits until the
first is disposed and then replaces the real starters), `ReplaceStarters_NullStarter_ThrowsAndHoldsNothing`, and, for item 4,
`SystemBrowser_Open_GoesThroughTheRecordedShellStart` and `WebView2Policy_OpenInSystemBrowser_GoesThroughTheRecordedShellStart` (an https
address and a mailto address, recorded, nothing opened). 19 tests in the class (14 before).
