## 1. Why

`ProcessStartInfo.UseShellExecute` is `true` by default on .NET Framework and `false` on .NET
(https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.useshellexecute). With `false` a start goes through
`CreateProcess`, which opens no document, folder or URL (only an executable) and refuses a program whose manifest asks for elevation or for UI
access (`ERROR_ELEVATION_REQUIRED`); only `ShellExecute` asks for consent
(https://learn.microsoft.com/windows/security/application-security/application-control/user-account-control/architecture). So every
start that does not redirect a standard stream sets `UseShellExecute=true` explicitly, today's value: **nothing changes on net48**. The starts
that redirect a stream already set `false` and stay as they are.

**The injectable starter.** `public static Func<ProcessStartInfo,Process> FuncStartProcessInfo` (default: `Process.Start(processStartInfo)`)
and `public static Func<Process,bool> FuncStartProcess` (default: `process.Start()`), as `ODDdeClient.FuncCreate`. Every start of the class
goes through one of them, except `Bash`'s. A test assigns recorders that keep the `ProcessStartInfo` or `Process` and return null/false, so
nothing is started, opened or shown. The return values keep `Process.Start`'s meaning: null when no new process was started (a document
handed to a program that was already running).

**Tests:** `tests/MiddleTierMockTests/ODFileUtilsStartTests.cs` (14 tests; the project already holds the CodeBase utility tests, ODThread
and the cancellation): every overload builds `UseShellExecute==true`, the file name and arguments as given (null arguments as `""`), no
redirect, no hidden window, no verb or working folder; the directory of `createDirIfNeeded` is made; the write-then-start overloads write
first (in a scratch folder under the temp folder); `ProcessStart(ProcessStartInfo)` and `ProcessStart(Process)` pass the caller's object
unchanged (an explicit `false` stays `false`); the defaults are the real starters (checked by name, not called). The recorders are asserted
to be in place before each call, so a mistake cannot start anything.

## 4. The source scan: `NoHqTests/ShellStartScanTests.cs` (last commit)

It reads the `.cs` files of the solution filter's C# projects, the shipped ones plus RdlDesign, DocumentationBuilder and CentralManager,
leaving out `tests\`, `tools\`, `third-party\`, `UnitTests`, `UnitTestsCore`, `xCrudGenerator` and NoHqTests (`bin\`/`obj\` skipped).
Comments and the contents of string and character literals are removed first (block comments and verbatim strings across lines).

- **No `Process.Start(string...)` outside `ODFileUtils.cs`:** a static `Process.Start(` (with or without `System.Diagnostics.`) is allowed only
  when its argument is a `new ProcessStartInfo(...)` in place or a variable the file declares as `ProcessStartInfo`. Instance starts
  (`process.Start()`) and `ODFileUtils.ProcessStart(...)` are not static starts.
- **Every `new Process(`/`new Process {`/`new ProcessStartInfo(`/`new ProcessStartInfo {` block sets `UseShellExecute`:** the block runs from
  the construction to the end of the first line at or after it that starts a process (`.Start(` or `ODFileUtils.ProcessStart(`), at most 80
  lines. A `new Process()` whose `StartInfo` is assigned from a variable passes, since that variable's own `new ProcessStartInfo(` block is
  checked.
- **Known pending:** `OpenPmsDental\Logic\PrefL.cs` (S3a-10's start of the update file copier). Its findings are written to the test output and
  do not fail; once S3a-10's fix is on main there are none. The entry is then removed (the lead, at or after the scan's merge).
- It asserts the scope (the projects in and out), more than 1000 files and at least 30 construction blocks.
- **Self-test:** 13 tests on synthetic lines: path starts found (one and two arguments, inside `using` and a lambda, spaces before the
  parenthesis); a start-info argument allowed (in place, declared variable) and an undeclared variable found; the helper file exempt;
  blocks without the flag found (`new Process()`, `new ProcessStartInfo(`, object initializers), with it allowed (also set in both branches
  of an `if`); a process with a checked start info allowed; each block checked on its own; the 80-line limit; instance starts, the helper's
  calls and other `.Start(` calls not taken for static starts; comments and strings ignored, code after them scanned; the comment and string
  remover itself.
- **Negative run** (`s3a2-scan-mutation.txt`): with `FormCreditCardManage.cs:335`'s new line removed and `FormPatientEdit.cs:1521` put back to
  `System.Diagnostics.Process.Start(mapUrl)`, the scan failed and named exactly those two sites; both were restored.
