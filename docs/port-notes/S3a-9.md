## 1. (i) File rights through `FileInfo` and `DirectoryInfo`

.NET (Core) has no static `File.GetAccessControl`/`SetAccessControl` or `Directory.GetAccessControl`/`SetAccessControl`; it has the
instance form as extension methods of `FileSystemAclExtensions` (https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemaclextensions),
which .NET Framework has as instance methods of `FileInfo` and `DirectoryInfo`. The same source compiles on both.

| Site | Before | After |
|---|---|---|
| `OpenPmsDentalDbSettings/OfficeCaFile.cs` `WriteProtectedFile` | `Directory.SetAccessControl(folder,...)`, `Directory.CreateDirectory(folder,security)`, `File.SetAccessControl(path,...)` | `new DirectoryInfo(folder).SetAccessControl(...)`, `new DirectoryInfo(folder).Create(security)`, `new FileInfo(path).SetAccessControl(...)` |
| `OfficeCaFile.cs` `CheckExisting` | `Directory`/`File.GetAccessControl(path,AccessControlSections.Owner)` | `new DirectoryInfo(path)`/`new FileInfo(path).GetAccessControl(AccessControlSections.Owner)` |
| `OpenPmsDentalDbSettings/DbSettingsRunner.cs` `ResetConfigFileRights` | `File.SetAccessControl(configPath,...)` | `new FileInfo(configPath).SetAccessControl(...)` |
| `OpenPmsDentalDbSettings/ClientCertificateStore.cs` `GrantUsersReadToPrivateKey` | `File.Get`/`SetAccessControl(pathKey,...)` | one `FileInfo` for the key file, its `GetAccessControl()`/`SetAccessControl(...)` |
| `tests/DbConnectionSecurityTests/ToolTests.cs` (3), `OwnerAnswersTests.cs` (5) | the static forms | the instance forms (one `FileSecurity`/`DirectorySecurity` read per check instead of two or three) |

`Directory.CreateDirectory(string,DirectorySecurity)` is the same kind of call (absent on .NET, `DirectoryInfo.Create(DirectorySecurity)`
on both), so it changed with the others in the same method.

**Same on .NET Framework.** In the reference source `FileInfo.GetAccessControl()` is `File.GetAccessControl(FullPath)` with the same
sections (Access, Owner, Group), `FileInfo.SetAccessControl(s)` is `File.SetAccessControl(FullPath,s)`, the `DirectoryInfo` methods are
the `Directory` ones on `FullPath`, and `DirectoryInfo.Create(DirectorySecurity)` and `Directory.CreateDirectory(path,DirectorySecurity)`
both call `Directory.InternalCreateDirectory` on the full path with the security. **Proof:** DbConnectionSecurityTests (250 tests, 247
passed, 3 skipped, the opt-in test-network and TLS-server cases, as before), among them
`OfficeCa_WriteCopy_ProtectsTheFolderAndTheFile_UsersMayOnlyRead`, `OfficeCa_WriteCopy_RefusesALinkOrAFileForTheFolder_AndWritesNothing`
(CheckExisting), `Record_IsWrittenProtected_ReadBack_AndDeleted` and `Apply_SetsTheConfigFilesRightsBackToTheFolders`
(ResetConfigFileRights). `GrantUsersReadToPrivateKey` is not run by any test: it changes the rights of a key under
`%ProgramData%\Microsoft\Crypto`, so the tests replace it (`ActionInsteadOfUsersReadGrantForTests`); its change is the two-line rewrite
above.

**Left for others (not in this package's files).**
- `OpenPmsDentalBusiness/Email/DirectCertificateImport.cs:1383,1385` (`File.GetAccessControl`/`SetAccessControl(pathKey,...)`, the
  Direct import's copy of the grant): added by DCFU4 after the survey, owned by no package of the plan. It does not compile on .NET 10
  as it is; the same two-line change fixes it (for the lead to assign).
- `WpfControlsOD/Frms/FrmAtoZFoldersCreate.xaml.cs:74` (`Directory.CreateDirectory(path,directorySecurity)`): the file belongs to S3a-2
  (its line 60); the fix is `new DirectoryInfo(path).Create(directorySecurity)`.
- `OfficeCaFile.cs:115`, `new FileStream(path,FileMode.CreateNew,FileSystemRights.Write,FileShare.None,4096,FileOptions.WriteThrough,
  fileSecurity)`: .NET has no such constructor and .NET Framework has no `FileInfo.Create(FileMode,FileSystemRights,...,FileSecurity)`
  (the .NET 6+ extension), so no one form compiles on both. It stays for 3b (S3b-0's compile pass), where it becomes
  `new FileInfo(pathTemp).Create(FileMode.CreateNew,FileSystemRights.Write,FileShare.None,4096,FileOptions.WriteThrough,security)`.

## 2. (ii) `ExternalException` next to the GDI+ `OutOfMemoryException` catches

On .NET 10, System.Drawing reports GDI+'s out-of-memory status as `ExternalException` instead of `OutOfMemoryException`
(https://learn.microsoft.com/en-us/dotnet/core/compatibility/windows-forms/10.0/system-drawing-outofmemory-externalexception). Each catch
became `catch(Exception ex) when(ex is OutOfMemoryException || ex is System.Runtime.InteropServices.ExternalException)` (fully qualified,
so no `using` can clash), with the reason in a comment:

| Site | What it does with it |
|---|---|
| `OpenPmsDentalBusiness/SheetFramework/SheetDrawingJob.cs:857` (`g.DrawImage` of a sheet's static image) | throws the "static image too high in quality" `OutOfMemoryException`, as before |
| `OpenPmsDental/SheetFramework/SheetPrintingJob.cs:498` (`pd_PrintPage`) | shows the message and cancels the print job, as before |
| `tests/ImagingDeviceManagerTests/CaptureSessionFilesTests.cs:121` (`Image.FromFile` of a 16-bit TIFF) | Inconclusive, as before |
| `OpenPmsDentalBusiness/Imaging/DicomImageReader.cs:204` | **not changed, comment only**: the parser decodes DICOM in managed code (no System.Drawing call; `BitmapDicom` is drawn later, outside this `try`), so the catch sees only a managed allocation failure, which stays `OutOfMemoryException` on .NET 10. A GDI+ catch there would map an unrelated `ExternalException` to "not enough memory". |

**Same on .NET Framework.** GDI+ out-of-memory is still `OutOfMemoryException` there and takes the same path. The one difference: a
GDI+ error that is an `ExternalException` on .NET Framework too (a generic GDI+ error while drawing a sheet image) used to leave
`pd_PrintPage` unhandled and now shows the message and cancels the job; on .NET 10 the two cannot be told apart, so the plan's change
takes both. **Proof:** the full build (0 errors), ImagingDeviceManagerTests (525 passed; `Gray16Tiff_ReadableByGdiPlus` passes, this
computer's GDI+ reads the file). The new branch cannot be triggered on .NET Framework (GDI+ would have to report out of memory); it is
checked by the 3b run.

**Left for S3a-2** (Known overlaps): `OpenPmsDental/Forms/FormClaimAttachment.cs:499` and `FormImageSelectClaimAttach.cs:515`, the other
two `OutOfMemoryException` catches of the repository. Every other mention of `OutOfMemoryException` (`CertificateKeyProvInfo`,
`DirectCertificateImport`, `ClientCertificateStore` "critical exception" checks, `EhrCodes.GetReadErrorText`) is about managed memory, not
GDI+.

## 3. (iii) The network guards also set `HttpClient.DefaultProxy`

`tools/DevDbTool/NetworkGuard.cs` and `tools/SyntheticData/Infrastructure/LocalOnly.cs` (`NetworkGuard`) routed every request to a dead
local proxy (`127.0.0.1:9`) through `WebRequest.DefaultWebProxy`. On .NET Framework `HttpClient` falls back to that proxy; on .NET (Core
3.0 and later) it uses `HttpClient.DefaultProxy` instead, so the guards would let `HttpClient` through on .NET 10. `Install` now also sets
`HttpClient.DefaultProxy` through the new public `SetHttpClientDefaultProxy(IWebProxy)`, which finds the property by reflection (it does
not exist on .NET Framework, so a direct assignment would not compile there) and returns whether it set it. SyntheticData gained a
`System.Net.Http` reference (DevDbTool had one).

**Same on .NET Framework:** the property is not found, nothing more is set, and `HttpClient` is blocked through
`WebRequest.DefaultWebProxy` as before. **Proof:** the new tests, two per guard, run on .NET Framework now and unchanged on .NET 10 in 3b:
`Install_SetsBothDefaultProxies_WhereTheRuntimeHasThem` (the dead proxy, nothing bypassed, the destination recorded; `HttpClient.DefaultProxy`
is the guard's proxy where it exists, `SetHttpClientDefaultProxy` returns false where it does not) and
`HttpClient_IsBlocked_AndItsDestinationRecorded` (a real `HttpClient` GET to `http://blocked.example.test/synthetic` fails and the guard
recorded it; the only connection is to `127.0.0.1:9`). Both put the two proxies back afterwards.
- SyntheticData's: `tools/SyntheticData/SyntheticData.Tests/NetworkGuardTests.cs` (SyntheticData.Tests: 60 tests, 59 passed, 1 skipped,
  `RealDump_Has422Tables`, as before).
- DevDbTool's: DevDbTool has no test project, and a project reference to the tool (an exe) from a test project would add a project to that
  project's `packages.lock.json`, which the lane restores in locked mode. So DbConnectionSecurityTests, which already holds the dev database
  TLS checks, compiles `tools/DevDbTool/NetworkGuard.cs` as a linked file and tests it in `DevDbNetworkGuardTests.cs`.

## 4. (iv) `PrefName` members obsolete as errors

On .NET 10 `XmlSerializer` serializes `[Obsolete]` members and throws while it builds a serializer for a member marked
`[Obsolete(IsError=true)]`, enum constants included
(https://learn.microsoft.com/en-us/dotnet/core/compatibility/serialization/10/xmlserializer-obsolete-properties). `PrefName` travels
through the Middle Tier. The 25 `[Obsolete("...",true)]` members of `PrefName` in `OpenPmsDentalBusiness/TableTypes/Pref.cs` are now
`[Obsolete("...",false)]` (no other change; the enum's summary says why): `AccountShowTrojanExpressCollect`,
`AgingNegativeAdjsByAdjDate`, `ApptModuleUses2019Overhaul`, `CloudAllowedIpAddresses`, `EConnectorEnabled`, `EmailInboxComputerName`, the
13 `InsBen*Codes`, `StatementShowCreditCard`, `StatementsUseSheets` and the four `TrojanExpressCollect*`. Before the change nothing named
any of them in code (it would not have compiled); after it the build has no new warning.

New `NoHqTests/ObsoletePrefNamesTests.cs` puts the lost compile error back:
- `PrefName_NoMemberIsObsoleteAsAnError`: reflection over all members (more than 1000); none has an `ObsoleteAttribute` with `IsError==true`, so a
  newly ported upstream preference marked that way fails on .NET Framework, not only on .NET 10. (Before this package it would have listed
  the 25.)
- `PrefName_TheFormerErrors_AreStillThere_AndObsolete`: the 25 names exist and are obsolete (not as errors), so the list stays true.
- `PrefName_TheFormerErrors_AreNamedByNoCodeOutsidePrefCs`: every `.cs` file under the repository root (about 7000; without `bin`, `obj`,
  `packages`, `third-party`, `node_modules`, `TestResults` and dot folders) except `Pref.cs`, with comments, strings, verbatim strings and
  character literals blanked (the code in interpolation holes kept), has no `PrefName.<name>` of the 25 (also fully qualified or with
  spaces around the dot). The convert scripts' SQL strings and comments are allowed.
- `Scanner_FindsCode_NotCommentsOrStrings`: the scanner itself on a made-up text: code, a qualified name, an interpolation hole and a
  verbatim interpolated hole are found; comments, block comments, strings with quotes and escapes, verbatim strings, a character literal,
  `{{` text and longer names are not.

**Same on .NET Framework:** `XmlSerializer` ignores obsolete members there; the compiler's error becomes a warning, and the tests replace
it. **Proof:** NoHqTests (61 passed, the 4 new ones among them); MiddleTierMockTests (125 passed), whose
`ObsoleteMemberRoundTripTests` (from S0-T) carry a `PrefName` argument and a `ClinicPref` through the mock Middle Tier's serializer.

## 5. (v) Addresses with two dots in a row

.NET 10's `MailAddress` refuses an address with consecutive dots (https://learn.microsoft.com/en-us/dotnet/core/compatibility/10,
Networking). Today, on .NET Framework (checked with Windows PowerShell 5.1 on CLR 4.0.30319 and pinned by the tests), `new
MailAddress("a..b@example.com")` and `MailAddressCollection.Add` take it.

| Site | Change |
|---|---|
| `OpenPmsDentalBusiness/Email/SendEmails.cs` `BasicEmailMessageToMailMessage` (the plan's 142-150; System.Net.Mail SMTP on ports other than 465, unsigned) | From through the new `ParseMailAddress`, To/Cc/Bcc through the new `AddMailAddresses` |
| `SendEmails.cs` `CreateMIMEMsg` (the plan's 259-268; Gmail, Microsoft 365, MailKit SMTP) | the same |
| `CodeBase/Utilities/EmailUtils.cs:16-18` `SendEmail` (no caller today) | From and To in a `try` with the same message (CodeBase has no `Lans`) |
| `OpenPmsDentalBusiness/Data Interface/EmailAddresses.cs:221` `GetValidMailAddress` | comment only: its bare `catch` already returns null (not valid) for any refusal, and its pattern already refuses two dots in a row on .NET Framework, so the result is null on both runtimes |

`ParseMailAddress` and `AddMailAddresses` turn a `FormatException` into an `ODException` "This is not a valid email address: <address>"
(`SendEmail.GetNotValidAddressText`, translated under "EmailMessages") with the `FormatException` as its inner exception. A blank address
still throws `ArgumentException`, as `MailAddress` does. The send wraps it, as any send error, in "Error sending email", and the e-mail
window's Details show it.

**What changes on .NET Framework:** only the error for an address that is not valid there either (for example `bob@`): it names the
address instead of `FormatException`'s "The specified string is not in the form required for an e-mail address." Every address that sends
today sends the same.

**Found while pinning:** today `CreateMIMEMsg` already refuses `a..b@example.com`, but in MimeKit, not in `MailAddress`: MimeKit's
`MailboxAddress` throws `MimeKit.ParseException` ("Invalid local-part at offset 0") for From, To, Cc and Bcc alike. So of the sending paths,
only the unsigned System.Net.Mail SMTP send (`BasicEmailMessageToMailMessage`) sends to such an address today, and the SMTP server decides.
On .NET 10 `MailAddress` refuses it first and every path gives the not-valid-address error. Mapping MimeKit's `ParseException` to the same
message on .NET Framework would change today's behaviour and is not in the row (owner question).

New `tests/LibraryUpdateTests/AddressRulesTests.cs` (LibraryUpdateTests: 138 passed):
- Today (3b changes these to the .NET 10 result, the not-valid-address error): `Today_MailAddress_TakesConsecutiveDots` (address, user,
  host; the collection),
  `Today_CreateMIMEMsg_MimeKitRefusesConsecutiveDots` (`ParseException` for each field), `Today_BasicEmailMessageToMailMessage_SendsToConsecutiveDots`.
- The same on both runtimes: `GetValidMailAddress_ConsecutiveDots_IsNotValid`; `NotValid_CreateMIMEMsg_SaysTheAddressIsNotValid`,
  `NotValid_BasicEmailMessageToMailMessage_SaysTheAddressIsNotValid` and `NotValid_EmailUtilsSendEmail_SaysTheAddressIsNotValid` (an
  address `MailAddress` refuses on both: the `ODException`, its exact message and the inner `FormatException`, for each field; EmailUtils
  refuses before `SmtpClient.Send`, so nothing connects); `BlankFrom_StaysAnArgumentException`.
