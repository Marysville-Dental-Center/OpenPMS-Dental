# Port note: UI-10 (text fit)

Package UI-10 of the UI refresh ([docs/specs/ui-refresh-plan.md](../specs/ui-refresh-plan.md), section 7's UI-10 row, with sections 3.4, 3.7, 5.3
and 5.4). The fit fixes are made for the new font (Segoe UI 9 pt, UQ-1) while `main` still shows today's font, so `main` never shows clipped text
once the font flips (UI-2b). One section per slice; sections 1 to 3 are the shared method.

## 1. The method

1. **Run the tier 1 scan** at the new font (UI-0b's tool, `tests/UiRefreshTests`, `docs/port-notes/UI-0b.md`). It builds every window and
   UserControl off screen, puts Segoe UI 9 through the token override `UiTheme.SetFontForTest` (the product's own font path), measures every
   control the way it draws, simulates the scales 1.2, 1.25, 1.5, 1.75 and 2, and records every control's bounds:
   ```
   set OPMS_UI_SCAN=1
   set OPMS_UI_SCAN_OUT=<a folder>
   powershell -NoProfile -ExecutionPolicy Bypass -File <od-tools>\run-tests.ps1 -Root . -Mode Targeted -Platform x64 -RequireBuildOutput -Include UiRefreshTests
   ```
   The files are in `<folder>\options` (`overflow-segoe9.tsv`, `selfsizing-segoe9.tsv`, `bounds-segoe9.tsv`, `bounds-record-before.tsv`,
   `bounds-record-segoe9.tsv`, `summary.txt`). The scan lists only what is new in the new font: a control that already overflows in today's font is not
   in it. The whole filter must be built first (the plain exes are read from their own build folders).
2. **Rank the files.** `python tools/UiFit/fit_tools.py scan-tsv --scan <folder>\options --out tests/UiRefreshTests/Data` writes
   `tests/UiRefreshTests/Data/fit-scan-files.tsv` (one row per designer file: new overflows, new self-sizing overlaps, bounds differences, how many need
   the owner, sorted by the sum, largest first) and `fit-scan.tsv` (every item at 100%, in the same file order). **A slice picks its files from
   `fit-scan-files.tsv` in rank order, at most about 40 designer files**, skipping the files earlier slices own (their rows are in `fit-fixes.tsv`).
   The committed TSVs are the scan of `main` before any fix (c3c610458); a later slice reruns the scan on the latest `main` and the tool, so it
   works from the latest run (plan 5.4). Windows whose designer code is in a `.cs` file without a `.designer.cs` (the report designer's dialogs) show as
   "(no designer file)" at the end of the ranking.
3. **Plan and apply the fixes.** `python tools/UiFit/fit_tools.py plan --scan <folder>\options --windows <type,type,...> --owner-out <tsv>
   --fixes-out tests/UiRefreshTests/Data/fit-fixes.tsv [--apply]` (without `--apply` it only reports). The rules, all at 100% designer pixels:
   - A control that does not size itself and overflows: `Width` and `Height` grow by the pixels missing, into the free space beside and below it only
     (up to the nearest sibling or the parent's edge; the scan's own free-space rule). If the free space is smaller than the need, the control takes
     what is free and the rest is a "needs the owner" item.
   - The pixels missing at the scales 1.25, 1.5, 1.75 and 2 (visibly cut ones only) are divided by the scale, rounded up, and added the same way.
   - A single-line text box that sizes itself and would grow into a neighbour (20 px at today's font, 23 at Segoe UI 9): `AutoSize = false` with
     today's `Size`; the new font's line (16 px) fits its 20 px less the 2 px borders. A pair of two such boxes is fixed on both.
   - A label, radio button or check box that sizes itself and grows into a neighbour or the parent's edge: `AutoSize = false` with the size the new font
     gives it, inside the free space (a radio button or check box keeps its height; the next scan adds what it still needs).
   - A combo box, date picker or up-down box (its height comes from the font): no size edit can keep it; listed for the owner.
   - A control that the window's designer file does not add (the children of another control: `ODDatePicker`'s boxes, a grid's scroll bars): not this
     file's; listed.
   The tool edits the designer as bytes (latin-1 round trip), changing only the digits of the `Size` line, one `AutoSize` word, or inserting one
   `this.x.AutoSize = false;` line before the `Location` line with that line's own line end: every line end and BOM stays (`tools/Test-NoEolFlips.ps1 -Base main`
   reports 0 flips). No `Location`, `Dock`, `Anchor`, `Margin`, `Padding`, `TabIndex` or font changes, ever.
4. **`tests/UiRefreshTests/Data/fit-fixes.tsv`**: one row per fixed control (designer file, window, control, fix `size` or `autosize-off`, a note with the
   size before and after). The layout snapshot test and the bounds comparison allow exactly these controls to differ (3.7). A row is kept per control; a
   later pass of the tool replaces it (and keeps `autosize-off`).
5. **Repeat** build (`OpenPmsDental` and `UiRefreshTests` through the lane) and scan until a pass changes nothing: a fix grows a control into free space,
   which changes the free space of its neighbours. Slice 1 needed four passes.
6. **Gallery G-UI3.** `tests/UiRefreshTests/FitGallery.cs` (opt-in, `OPMS_UI_FIT_GALLERY` names the folder; `OPMS_UI_FIT_GALLERY_WINDOWS` the window types,
   default the slice 1 list; `OPMS_UI_FIT_GALLERY_OWNER` a TSV of the "needs the owner" controls, each cropped and outlined in red into `owner\`) draws the
   slice's windows in Segoe UI 9 through the token override, off screen (`DesignSheetWindows.Capture`: nothing is shown, no database). Run it before the
   slice's fixes into the before folder and after them into the after folder, then `tools/New-UiGallery.ps1 -Before ... -After ... -Name G-UI3 -Out ...`.

## 2. What the scan cannot fix by a size edit

- Text longer than the room with no free space (a label that runs to its group box's edge, a check box in a full row): needs the owner. The best fix that
  keeps the layout's intent is made where it is possible (grow into the free space, or wrap a label taller into free space); the rest is listed with a
  picture.
- 1 or 2 px of height with the ink inside the box (the control's text box is a pixel short, the letters are whole): not visibly cut, listed without a picture.
- Controls that lay out their own children from the font (`ODDatePicker`: its text box, drop button and calendar; a grid's scroll bars; the up-down boxes):
  their own control package (UI-4b, UI-5) owns them.
- A combo box, date picker or up-down box that grows into a neighbour (height from the font).

## 3. How a later slice starts

`git switch -c ui/ui10-N main`, build the filter, run the scan (section 1, step 1), `scan-tsv` into a scratch folder (not the committed TSVs, unless the
slice is the one that refreshes them), pick the next files from `fit-scan-files.tsv` that are not in `fit-fixes.tsv`, list their window type names, run
`plan` without `--apply` to see the counts, then with it. Commit each pass. The gallery windows list is the slice's window types.
