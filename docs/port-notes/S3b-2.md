### A.2 The SYSLIB replacements (S3b-0 item 1), same behaviour

| Where | Was (diagnostic) | Now | Why it behaves the same |
|---|---|---|---|
| `ODCrypt/CryptUtil.cs` | `new RNGCryptoServiceProvider()` (SYSLIB0023) | `RandomNumberGenerator.Create()` | On .NET both are the system CSPRNG (BCryptGenRandom); thread safe, shared. |
| `CodeBase/Crypto/HmacSha256.cs` | `new SHA256CryptoServiceProvider()` x2 (SYSLIB0021) | `SHA256.Create()` | On .NET every SHA-256 class is the CNG implementation; the class existed because .NET Framework's `HMACSHA256` used `SHA256Managed`, which fails under the FIPS policy; CNG does not (comment updated). |
| `CodeBase/Crypto/SecretBox.cs`, `CodeBase/Utilities/MiscUtils.cs` (x2) | `new AesCryptoServiceProvider()` (SYSLIB0021) | `Aes.Create()` | The same OS AES; the code sets key size, key, IV, mode and padding (SecretBox) or relies on the same defaults, CBC and PKCS7 (MiscUtils). CryptoTests' known ciphertexts pass. |
| `CodeBase/Utilities/VendorDirect/VendorHttp.cs` | `new X509Certificate2(byte[], string, flags)` (SYSLIB0057) | `X509CertificateLoader.LoadPkcs12(bytes, password, flags)` | The PKCS#12 loader with the same flags (`EphemeralKeySet` or `UserKeySet`); the loader's default limits apply. |
| `DataConnectionBase/OfficeCaServerVerifier.cs`, `OpenPmsDentalDbSettings/OfficeCaFile.cs` | `new X509Certificate2(byte[])` x2 each (SYSLIB0057) | `X509CertificateLoader.LoadCertificate(bytes)`, after a `X509Certificate2.GetCertContentType(bytes)==X509ContentType.Pkcs12` check | One DER or PEM certificate, which is what both read (PEM blocks decoded, else the file as DER) and what their messages say they accept ("PEM or DER"); a malformed file throws `CryptographicException` as before. What the old constructor accepted in practice: DER, PEM (through the regex) and a PFX without a password, which loaded with its key and was then refused by the `HasPrivateKey` check ("holds a private key ... never the CA's key"). `LoadCertificate` throws on any PKCS#12 blob, so both files now recognize a PFX by its content type first and refuse it with the private-key message, as before (DbConnectionSecurityTests' `OfficeCa_PemOrDer_ACaOnly` pins it); the `HasPrivateKey` check stays as defence in depth. A PKCS#7 file changes nothing in practice: a Windows-export `.p7b` failed on net48 too ("Cannot find the original signer"), and a signed PKCS#7 gave only the signer's certificate; it now gets the "not a certificate file (PEM or DER)" message. |
| `CodeBase/Utilities/ODPrimitiveExtensions.cs` (`DeepClone`) | `FormatterServices.GetUninitializedObject` (SYSLIB0050) | `RuntimeHelpers.GetUninitializedObject` | What the old method calls on .NET. |
| `CodeBase/Utilities/ODException.cs`, `ImagingDeviceManager/ImagingDeviceException.cs`, `DataConnectionBase/DbConnectionSecurity.cs` (`DbConnectionRefusedException`) | serialization constructor and `GetObjectData` override (SYSLIB0051, CS0672) | kept, marked `[Obsolete(..., DiagnosticId = "SYSLIB0051")]` as the base members are | Formatter-based serialization does not exist on .NET (BinaryFormatter is gone); nothing in the repository serializes these exceptions. Kept under the no-cut rule, as Microsoft's guidance allows (https://learn.microsoft.com/en-us/dotnet/fundamentals/syslib-diagnostics/syslib0051). |
| `CodeBase/Utilities/ODInitialize.cs` | `ServicePointManager.SecurityProtocol \|= Tls12` (SYSLIB0014) | removed (the row) | On .NET the default `SystemDefault` lets Windows choose TLS 1.2 and 1.3, and `HttpClient` does not read the setting. |
| `tests/CryptoTests/SecretsTests.cs` | `new AesManaged()` (SYSLIB0021) | `Aes.Create()` | On .NET `AesManaged` wraps the same implementation. |

Not in S3b-0's list and left as warnings, with a reason: `OpenPmsDentalDbSettings/ClientCertificateStore.cs` reads
`X509Certificate2.PrivateKey` (SYSLIB0028, `GetCapiRsaPrivateKey`) and imports the client `.pfx` with `X509Certificate2Collection.Import`
(SYSLIB0057, `ImportCollection`). Both still work on .NET 10. Their replacements change behaviour that only DbConnectionSecurityTests
check: `GetRSAPrivateKey` returns a key object the caller owns (the certificate keeps the `PrivateKey` one), and
`X509CertificateLoader.LoadPkcs12CollectionFromFile` with its default limits does not keep the storage provider a `.pfx` names, so Windows
could store the key in another key set than the CAPI container DIRECT-CERT's code expects. They are replaced, with
`Pkcs12LoaderLimits` that keep the provider and key name, when DbConnectionSecurityTests run on .NET 10 (S3b-5, after S3b-3 moves the
business library they reference). `HttpRequestMessage.Properties` (CS0618 x8, `VendorHttp.cs`) still works on .NET (it is backed by
`Options`) and stays for now.

### A.3 Code pages and TLS at start-up

- `ODInitialize.Initialize()` calls `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` as its first statement
  (https://learn.microsoft.com/en-us/dotnet/api/system.text.codepagesencodingprovider): .NET has only the Unicode encodings, ASCII and
  Latin-1 built in, and `ODEncodings.GetAnsiEncoding` and every reader of ANSI text need 1252 and the other pages (S3b-0 item 6). Registering
  twice is harmless.
- Every `Main` of part A that does not call `ODInitialize` registers it first too: `UpdateFileCopier/Program.cs`,
  `OpenPmsDentalDbSettings/Program.cs`, `tools/SyntheticData/Program.cs`. The `Main`s of the other exes (HL7, ServiceManager,
  DatabaseIntegrityCheck, MySQLManager, xCrudGenerator, RdlDesign, CentralManager, DocumentationBuilder) are S3b-3/S3b-4's and part B's.
- `ServicePointManager.SecurityProtocol` is gone (A.2).
