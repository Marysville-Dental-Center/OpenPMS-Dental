### B2. RDL `<Code>` blocks keep working (decision 14)

`RdlEngine/Definition/Code.cs` generated a Visual Basic source around a report's `<Code>` block (`Imports System`, `Namespace
fyiReporting.vbgen`, `Public Class MyClassN`, `Sub New()`, the block, `End Class`, `End Namespace`) and compiled it with
`VBCodeProvider.CompileAssemblyFromSource`, which throws `PlatformNotSupportedException` on .NET (S3b-0 item 3). The new
`RdlEngine/Definition/VbCodeCompiler.cs` compiles the same source with Roslyn (`Microsoft.CodeAnalysis.VisualBasic` 5.12.0) and loads the
emitted assembly from memory (`Assembly.Load(byte[])`; CodeDom wrote a temporary DLL and loaded it with `Assembly.LoadFrom`). `Code.cs`
keeps its generated source (the `AppendFormat` of each line included) and its message, `Code element has n error(s).  Line numbers are relative
to Code element.` with `Line n 'text' : BCnnnnn message` per error, n being the generated line minus 5.

**What the .NET Framework compile was,** measured with the .NET Framework 4.8 `vbc.exe` that CodeDom runs (14.8, "Visual Basic 2012"), with
the program's `CompilerParameters` (only `System.dll` referenced), in the 32-bit Windows PowerShell 5.1: no project-wide imports (`UCase`
unqualified is BC30451), no other reference (`System.Linq`, `System.Data` and `System.Xml` are not known), Option Strict Off,
Option Explicit On, **Option Infer Off** (`Dim x = 5 : x = "abc"` keeps "abc"), Option Compare Binary, warnings not reported (a function
without a return compiled), errors in the order of their place in the source. `VbCodeCompiler` uses the same options and language version
(`LanguageVersion.VisualBasic11`), no global imports, errors only, sorted by line and column. The S3b-0 spike had used Option Infer on and a
global import of Microsoft.VisualBasic; neither is what the program did, so neither is used.

**References.** The same assemblies cannot be named on .NET. `VbCodeCompiler` references the runtime's assemblies: the trusted platform
assemblies (`TRUSTED_PLATFORM_ASSEMBLIES`) in the folder of the core library whose names start with `System.`, `Microsoft.VisualBasic` or
`Microsoft.Win32.`, and `mscorlib` and `netstandard` (the program folder of the self-contained program, the shared framework's folder of a test
host). So a block may use more of the base library than mscorlib, System.dll and the VB runtime gave it (System.Linq, for one); every block
that compiled before still compiles. The list is built once per process (`Lazy`).

**The one difference found:** after a syntax error, Roslyn 5.12 also reports the missing `)` (BC30198, `')' expected.`) where vbc 14.8
reported only BC30201 (`Expression expected.`). Every error vbc reported is there, with the same line, text, number and message, in the
same order; such a block's count is one higher. A semantic error (BC30451) gives the identical message. RdlCodeTests pins this.

**RdlDesign's syntax check** (`CodeCtl.cs`, Check Syntax) called the same `VBCodeProvider`; it now calls `VbCodeCompiler.Check`, and the check
itself is the static `CodeCtl.CheckCode(string)`, which returns the error list's `Ln n- message` lines (the window adds them to its list, or
says "No errors" as before).

**Doubles without a format** (`Style.GetFormatedString`, which S3a-4 named as a 3b difference): .NET Framework's `ToString()` wrote a double
with 15 significant digits and a float with 7, zero without a sign; .NET writes the shortest round-trip text (`0.8999999999999999` for `0.3 *
3`, `-0`). The new `Style.ToStringNoFormat` writes "G15"/"G7" and drops the sign of zero, in the current culture as before, for the three
no-format paths. Without it the S3a-4 golden report shows `0.8999999999999999` and `3703.6800000000003`. A double **with** a format
(`ToString(format)`) is left as it is; .NET Framework rounded to 15 digits before a custom format, .NET formats the exact value (for one,
`1.005.ToString("0.00")` is `1.01` on .NET Framework and `1.00` on .NET). That is the program-wide change of .NET Core 3.0 that S3a-3 handled
for the program's own money texts; in reports it shows only for a value whose 15-digit rounding moves a half-way digit. Not changed here: a
**finding for the lead** (a report test of a formatted half-way value, or the same G15 step before the format, decided once for all reports).

### B3. SQL Server, ODBC and OLE DB (open point O-10)

`System.Data.SqlClient`, `System.Data.Odbc` and `System.Data.OleDb` are part of .NET Framework's System.Data and packages on .NET (none in the
offline folder; the row and O-10 move them with the port of the RDL providers). Nothing is deleted:
- **RdlEngine** (`Runtime/RdlEngineConfig.cs`): `GetConnection` for the providers `SQL`, `ODBC` and `OLEDB` still calls the host's
  `CheckConnection` hook first, with the same class names (`System.Data.SqlClient.SqlConnection` and the like, now constants), so the
  program's connection rule refuses as before (DbConnectionSecurityTests' `RdlEngine_CallsTheHook_BeforeItCreatesAConnection`); then, on
  .NET, it throws `NotSupportedException`: "The data provider 'ODBC' (SQL Server, ODBC or OLE DB) is not available yet in the .NET 10 build of
  the report engine: its port is open point O-10 of the .NET 10 plan (docs/specs/net10-plan.md). Reports on the MySQL.NET data provider are
  not affected." The engine shows it as the data source's error. The .NET Framework code (`new SqlConnection(...)` and the others) is kept
  under `#if NETFRAMEWORK`; `SQL` with an empty connection string still makes no connection. `GetTableSelect`'s MySQL-over-ODBC check reads
  the connection's class name and `Driver` by reflection, so it needs no reference and works again once the package is there. Seven engine
  files lose an unused `using` of the three namespaces.
- **RdlDesign**: `DesignerUtility.cs` (the two `catch (SqlException)` blocks, the three `GetSchema` overloads and their `is` checks, the usings)
  and `DialogDatabase.cs` (usings only) keep that code under `#if NETFRAMEWORK`. On .NET the designer's existing catches show the engine's
  O-10 message (Test Connection: "Unable to open connection"; the schema and column lists: "Error"). `DialogDataSourceRef.cs` and
  `DialogDataSources.cs` only name the providers and the ODBC DSN list (the registry), which work on .NET; unchanged.

### B4. RdlDesign: the toolbar and the status bar (WFDEV006)

`RdlDesigner.cs` still used the WinForms `ToolBar` and `StatusBar` (with `StatusBarPanel`), which .NET has only as shims that cannot be
created; WFDEV006 is an error (`Directory.Build.Net.props`). S3a-M3 left them (its note, section 9). The toolbar only held controls (no
`ToolBarButton`): it is a `Panel` docked at the top with the same name, border, size and controls (`ShowToolTips` and `DropDownArrows` were for
toolbar buttons and go). The status bar is a `StatusStrip` with three `ToolStripStatusLabel`s: the first springs (was `Spring`), the second
(the selected item's name) and third (its position) size to their text with the sunken and raised borders and the same tool tips
(`ShowItemToolTips`); the property sets keep their order (`Dock`, then `Anchor`, `Size`, `Location`). They look slightly different (a launch
check on a test PC, with the WINCHK harness's RdlDesigner checks); the texts the designer writes into them are unchanged.

  `RdlReport_VbCodeFunctions_Pages` should pass as it is (B2; RdlCodeTests runs the same report against its record now). ReportTests runs
  `RdlCodeBlockReportTests`.
- **S3b-7:** the two Roslyn DLLs ship with the program (MIT; THIRD-PARTY-NOTICES, the row names Roslyn), and the release's file lists name them.
- **O-10:** when the providers are ported, the `#if NETFRAMEWORK` blocks of `RdlEngineConfig.cs`, `DesignerUtility.cs` and `DialogDatabase.cs`

- **Lead (finding, B2):** formatted doubles in reports follow .NET's exact formatting.
- **Pre-existing, not changed:** `Code.cs` and `CodeCtl.cs` append each generated line with `StringBuilder.AppendFormat(line + "\r\n")`, so a
  `<Code>` line with `{` or `}` (an array initializer) throws `FormatException` while the report is parsed, on .NET Framework too. Kept, as the
  generated source must stay the same; a fix would be a separate decision.
