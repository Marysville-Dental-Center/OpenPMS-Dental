# Port note: S3a-5 (PasswordVault to Windows Credential Manager)

Package S3a-5 of stage 3a of the .NET 10 move ([docs/specs/net10-plan.md](../specs/net10-plan.md), the S3a-5 row): branch `net10/s3a5-1`
from `main` (`ed9914827`). The saved Middle Tier logins move from the Windows Runtime `PasswordVault` to the Windows Credential Manager,
through `advapi32.dll` (`CredWriteW`, `CredReadW`, `CredDeleteW`, `CredEnumerateW`, `CredFree`), behind the same public interface. .NET 5
and later cannot consume `.winmd` files (https://learn.microsoft.com/en-us/dotnet/core/compatibility/interop/5.0/built-in-support-for-winrt-removed),
so `PasswordVaultWrapper.csproj` drops its `Windows.winmd` reference and `Required dlls/Windows.winmd` is deleted.

## 1. Design (the spec, written before the code)

**The public interface stays.** `PasswordVaultWrapper.WindowsPasswordVaultWrapper` keeps its four static methods and their signatures:
`WritePassword(uri,username,password)`, `TryRetrieveUserName(uri,out username)`, `RetrievePassword(uri,username)` and
`ClearCredentials(uri)`. The callers (`OpenPmsDentalBusiness/Data Interface/CentralConnections.cs`, `CentralManager/Db/CentralConfigHelper.cs`,
`CentralManager/FormCentralManager.cs`) are not changed.

**Where a login is stored.** One generic credential (`CRED_TYPE_GENERIC`) per Middle Tier address and user, for the signed-in Windows user on
this computer only (`CRED_PERSIST_LOCAL_MACHINE`: it does not roam, as the PasswordVault entries did not):

- target name `OpenPmsDental Middle Tier:<uri>|<username>`; the credential's user name is `<username>`; the secret is the password in
  UTF-16 (at most 1280 characters, the Credential Manager's limit of 2560 bytes).
- A login is found by enumerating `OpenPmsDental Middle Tier:*` and keeping only the entries whose target name is exactly the one computed
  from the address and the entry's own user name, so an address that is the start of another one never matches it.

**The one-time migration.** On the first use of any of the four methods in a process, the wrapper looks for its record,
the generic credential `OpenPmsDental Middle Tier migration from PasswordVault`. Without it, on .NET Framework it reads the old vault
through the Windows Runtime without any `.winmd` reference (`Type.GetType("Windows.Security.Credentials.PasswordVault,
Windows.Security.Credentials, ContentType=WindowsRuntime")`, called by reflection), lists the vault's entries (names only), keeps the ones
whose resource starts with this program's resource name `OpenDental Middle Tier:` (the name Open Dental and this program wrote), reads the
password of those only, and writes each one to the Credential Manager unless a login for that address and user is already there. Then it
writes the record (when, how many copied, how many already there, how many failed). The old vault entries are left in place (an older
release still finds them), except that `ClearCredentials` also removes the old entries of the address it clears, so a cleared login cannot
come back. If the vault cannot be listed (an error other than "not found"), no record is written and the next start tries again. On .NET 10
(stage 3b) the vault is not read and no record is written: the bridge release runs the migration first.

**Behaviour kept.** A blank user name or password throws (Windows could not store a blank password before either). `RetrievePassword`
throws when there is no such login. `TryRetrieveUserName` returns false on any error. `ClearCredentials` no longer throws when there is
nothing to clear (PasswordVault threw "element not found"; no caller depended on it).

**Tests (the owner's safety rules).** The tests run on the developer's own Windows account, so every test works through a store whose
names all start with a per-run prefix `OpenPmsDentalTest:<guid>:` (Credential Manager targets, old-vault resources and the migration record).
They create, read and delete only entries under that prefix, filter every enumeration by it before touching an entry, never call the
public static methods (which would run the real migration), and clean up in `finally`.
