# Port note: S3a-7 (Windows services without InstallUtil)

Package S3a-7 of stage 3a, wave 1, of the .NET 10 move ([docs/specs/net10-plan.md](../specs/net10-plan.md), the S3a-7 row and the Known
overlaps paragraph; section 3; https://learn.microsoft.com/en-us/dotnet/core/porting/net-framework-tech-unavailable): branch `net10/s3a7-1`
from `main` (`939baf67c`). `System.Configuration.Install` does not exist on .NET, and InstallUtil.exe cannot load a .NET 10 assembly, so
`CodeBase/Utilities/ServicesHelper.cs` now installs and removes services with the Windows Service Controller, `sc.exe`. No schema change,
no new package, nothing downloaded, no program started, and no test runs `sc.exe` or touches a real service.

Commits: `1e7f134b9` (ServicesHelper, the HL7 project, FormServiceManage), `719af9ce9` (the tests), and this note with the plan's status line.

## 2. The sc.exe command lines

`sc.exe` is always `Path.Combine(Environment.SystemDirectory,"sc.exe")`: `C:\Windows\System32\sc.exe`, which file system redirection
turns into `C:\Windows\SysWOW64\sc.exe` for the 32-bit program on 64-bit Windows (Windows ships both). Never a `sc.exe` from the PATH or the current folder.

Install (`ServicesHelper.Install`, working folder the exe's folder), for example the HL7 service from the default install folder:

```
sc.exe create "OpenPmsDentalHL7" binPath= "\"C:\Program Files (x86)\Open PMS - Dental\OpenPmsDentalHL7\OpenPmsDentalHL7.exe\"" type= own start= auto error= normal obj= LocalSystem DisplayName= "OpenPmsDentalHL7"
```

- `binPath=` carries the quotes into the ImagePath (`"C:\...\OpenPmsDentalHL7.exe"`), as InstallUtil's ServiceInstaller wrote it. The HL7
  service's `Program.cs` strips the quotes and compares the ImagePath's folder with its own to find its service name, so nothing may follow
  the path.
- `sc.exe` needs the space after each `=`.
- No `sc.exe description` and no `sc.exe config` follow: the installer set no description and no delayed start.

Uninstall (`ServicesHelper.Uninstall`), after reading the service's ImagePath from `HKLM\System\CurrentControlSet\Services\<name>`:

```
sc.exe delete "OpenPmsDentalHL7"
```

Then, only when the delete succeeded, the service is stopped and waited for (`ServicesHelper.Stop`, 7 seconds): Windows removes a service
marked for deletion once it has stopped. This is ServiceInstaller's order (delete, then stop), so a delete refused for lack of rights leaves a
running service running. A service whose ImagePath is a `mysqld.exe` is removed as before: stopped, then `CMD.exe /C mysqld.exe --remove
<name>` from its `bin` folder.

A name that is empty or holds `"`, `/` or `\`, and an exe path that is not a full path or holds `"`, are refused with `ArgumentException`
before any process starts.

The exit code of `sc.exe` is the Win32 error (`GetScErrorCode` also reads a `[SC] ... FAILED nnnn:` line when the exit code is 0):

| Code | Meaning | `GetScErrorText` |
|---|---|---|
| 0 | success (`[SC] CreateService SUCCESS`, `[SC] DeleteService SUCCESS`) | empty |
| 5 | `ERROR_ACCESS_DENIED`: not run as administrator | Access is denied. Installing or removing a service needs an administrator: run the program as administrator. |
| 1060 | `ERROR_SERVICE_DOES_NOT_EXIST` | No service with this name is installed. |
| 1072 | `ERROR_SERVICE_MARKED_FOR_DELETE` | The service is already marked for removal. Close the Services window and any program that has the service open, or restart the computer. |
| 1073 | `ERROR_SERVICE_EXISTS` | A service with this name is already installed. |
| other | | sc.exe failed with error N. |

`Install(string,FileInfo)` (the program's call, PrefL) still decides by looking the service up afterwards and still grants Everyone
start/stop (`sc sdshow`/`sc sdset` through `cmd.exe`, unchanged).

## 3. The pinned service settings

Read from `OpenPmsDentalHL7/ProjectInstaller.cs` before it was deleted, and from what InstallUtil's `ServiceInstaller`/`ServiceProcessInstaller`
did with them; pinned in `ServiceInstallTests.ScCreate_HasTheProjectInstallersSettings`:

| Setting | ProjectInstaller / ServiceInstaller | sc.exe |
|---|---|---|
| Service name | `ProgramNames.HL7ServiceName` (`OpenPmsDentalHL7`), or InstallUtil's `/ServiceName=<name>` (what ServiceManager passed) | the name ServiceManager or the program passes, `create "<name>"` |
| Display name | not set (ServiceInstaller's default is empty), so Windows shows the service name | `DisplayName= "<name>"`, the service name |
| Description | not set | none (no `sc description`) |
| Start type | `ServiceStartMode.Automatic`, delayed start left false | `start= auto` |
| Account | `ServiceAccount.LocalSystem` | `obj= LocalSystem` |
| Service type | Win32OwnProcess (one service in the exe) | `type= own` |
| Error control | `SERVICE_ERROR_NORMAL` | `error= normal` |
| ImagePath | the exe's full path in quotes | `binPath= "\"<path>\""` |
| Dependencies | none | none |

ServiceManager installs every service with these settings, as InstallUtil did for the HL7 service. The Open Dental exes it also offers
(`OpenDentalService.exe`, `OpenDentalEConnector.exe` and the others, not built from this repository) had their own installers, which this
repository never had; they now get the same settings. Not done by sc.exe and left as it is: InstallUtil's ServiceInstaller also registered an
Application event log source named after the service at install and removed it at uninstall. The HL7 service runs as LocalSystem, so Windows
creates the source at its first event log write; a source left behind after a removal does no harm.

## 4. Elevation

Installing and removing a service needs an administrator. ServiceManager runs elevated by its manifest (`requireAdministrator`), so its
`sc.exe` child runs elevated too; the start redirects output (`UseShellExecute=false`, CreateProcess), which is fine from an elevated parent.
The program's own call (PrefL's `TryInstallOpenDentalService`) is not elevated: `sc.exe` then exits with 5, the service is not found
afterwards, and the program keeps today's "try running as admin" alert.

## 5. Tests

No test creates, deletes, starts, stops or configures a real Windows service, and none runs `sc.exe` (owner rule: agents and tests change no
system or security settings). Each test of `tests/ReleaseFlowTests/ServiceInstallTests.cs` replaces `FuncRunProcess`, `FuncGetImagePath`
and `FuncStopService` with fakes that record the calls and answer with canned `sc.exe` output, and puts the real ones back in `TestCleanup`
(the class is `DoNotParallelize`). They check the exact command lines, the single `sc.exe create` of Install, the delete-then-stop order, no
stop after a failed delete, the MySQL branch, the 1060/1073/5 codes and their texts, the parsing of `FAILED nnnn:`, and the refused names and
paths.

- `ProgramNamesTests.HL7Service_InstallUtilFindsItsInstaller` (which called `AssemblyInstaller.CheckIfInstallable`, line 191) is now
  `HL7Service_HasNoInstallUtilInstaller`: `ProjectInstaller.cs` is gone, no HL7 source or the project names `System.Configuration.Install`
  or `RunInstaller`, and the built assembly, loaded through S3a-8's `ProgramAssembly.Load` (the `.dll` beside a .NET apphost, else the
  `.exe`), references no `System.Configuration.Install` and still has `OpenPmsDentalHL7.ServiceHL7 : ServiceBase`.
  `RuntimeNameSites_UseProgramNames` no longer lists the deleted file.
- `BINBTests.RemovedBinariesTests.ServiceManager_DoesNotReferenceInstallUtil`: ServicesHelper's code (comments left out) names no InstallUtil
  and no `RuntimeEnvironment.GetRuntimeDirectory()`, and runs `Path.Combine(Environment.SystemDirectory,"sc.exe")`.

Targeted runs: ReleaseFlowTests, BINBTests, NoHqTests, MiddleTierMockTests (results in the package report).

## 6. Manual check: install and remove the HL7 service on a test PC

For a person, on a test PC, never on a server in use. It changes the PC's services, so it is not run by an agent.

1. Build Debug|x86 or take a bridge release build. Copy `ServiceManager` and the `OpenPmsDentalHL7` folder (with the files of its build
   output) to the test PC, for example under `C:\Program Files (x86)\Open PMS - Dental\`.
2. Open an elevated Command Prompt and run `sc.exe query OpenPmsDentalHL7`. Expect `FAILED 1060` (not installed). If it is installed, remove
   it first (step 8) or use another name that starts with `OpenPmsDental`.
3. Start `ServiceManager.exe`. Windows asks for administrator consent (its manifest); accept.
4. Click Add. In the window, type the name `OpenPmsDentalHL7`, browse to `OpenPmsDentalHL7\OpenPmsDentalHL7.exe`, click Install. Expect no
   error message and the status "Installed, Stopped".
5. In the Command Prompt run `sc.exe qc OpenPmsDentalHL7` and check: `TYPE : 10 WIN32_OWN_PROCESS`, `START_TYPE : 2 AUTO_START` (not
   `(DELAYED)`), `ERROR_CONTROL : 1 NORMAL`, `BINARY_PATH_NAME : "C:\...\OpenPmsDentalHL7\OpenPmsDentalHL7.exe"` (with the quotes, nothing
   after them), `DISPLAY_NAME : OpenPmsDentalHL7`, `SERVICE_START_NAME : LocalSystem`. Run `sc.exe qdescription OpenPmsDentalHL7`: the
   description is empty. Run `sc.exe sdshow OpenPmsDentalHL7`: it holds `(A;;RPWPCR;;;WD)` (Everyone may start and stop it).
6. Click Install again for the same name (Add, same name and exe). Expect `Error. Exit code: 1073` and "A service with this name is
   already installed."
7. Optional, with an HL7 setup in a test database: click Start, check the status "Installed, Running" and the Application event log.
8. In ServiceManager select the service and click Uninstall. Expect no error message; the service disappears from the list (if it was
   running, it is stopped and removed). `sc.exe query OpenPmsDentalHL7` answers `FAILED 1060`.
9. Click Uninstall from a window opened for a name that no longer exists (or repeat step 8 from a second, stale window): expect
   `Error. Exit code: 1060` and "No service with this name is installed."
10. Optional: start ServiceManager as a standard user with consent refused; it does not start. The program's own install of
    OpenDentalService, as a standard user, shows the alert "Failed to install OpenDentalService, try running as admin."
