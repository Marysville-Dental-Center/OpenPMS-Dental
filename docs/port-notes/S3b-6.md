## 1. The server: OpenPmsDentalServer on ASP.NET Core

`OpenPmsDentalServer.csproj` is a new `Microsoft.NET.Sdk.Web` project with the old file name and GUID (the solution's Project line is
unchanged; its x64 platforms now map to `Debug|x64`/`Release|x64`, where S3b-1 had to map them to x86 for the classic project). No target
framework of its own: `Directory.Build.props` gives it `net10.0-windows`, and `Directory.Build.Net.props` (imported by the Web SDK's

`Microsoft.Extensions.Hosting.WindowsServices` (batch D). C# 8.0, pinned: the host is written without the C# 10 forms of the minimal API
(S3b-0 item 4 allowed either); `WebApplicationOptions` has init-only setters, so the content root goes in as `--contentRoot` with the
arguments. `Properties\AssemblyInfo.cs` (24.3.63.0) and the shared assembly info link stay, so `ReleaseFilesTests.cs:31` holds unchanged.
`OpenDentalServerConfig.xml` stays the sample of the database settings and, as before, is not copied by the build (an edited copy next to
the exe is never overwritten).

**The endpoint** (`MiddleTierEndpoint.HandleAsync`, the server's only request delegate):
1. Not HTTPS: 403. Kestrel listens on HTTPS only; this also refuses a plain HTTP binding of IIS.
2. The path: IIS gives the application's virtual path as the request's `PathBase`; on Kestrel and the test server the configured `PathBase`
   is matched (case-insensitive). Then the rest must be `/ServiceMain.asmx` (any case), `/` or empty; otherwise 404. The application name
   given to the business layer is that path base (`/OpenDentalServer`), or `/` at the site root, as `HostingEnvironment.ApplicationVirtualPath`
   gave it, so `{application name}Config.xml` is still found for several applications on one host.
3. Not POST: 405 with `Allow: POST`.
4. The body: the request's `IHttpMaxRequestBodySizeFeature` gets the limit; a `Content-Length` above it, or more bytes than it while reading
   (counted here, because the test server has no limit of its own), or Kestrel's/IIS's own 413: 413 with "The request is larger than the
   Middle Tier server accepts (N bytes, MiddleTier:MaxRequestBodySize)". The body is decoded as UTF-8 (a byte order mark dropped, invalid
   bytes replaced, as StreamReader read it).
5. `DtoProcessor.ProcessDto(dto,contentRoot,applicationName,clientIp)`, the host form S0-4 made, **on a new thread of the request's own,
   synchronously from start to end**: the business layer keeps a request's state in thread-static fields (`RemotingClient`'s role,
   `Security.CurUser`/`PasswordTyped`/`CurComputerName`, `MiddleTierHost`), so a request runs on one thread, and a new thread starts with none
   of another request's values. The thread first calls `RemotingClient.SetRemotingRoleT(MiddleTierRole.ServerMT)` (the role per request;
   `Configure` also sets it for the process, which the business layer's own threads read), inside
   `AssemblyLoadContext.EnterContextualReflection` for the server's assembly, so `Type.GetType` of the method's class, the XmlSerializer's
   generated serializers and plug-ins resolve in the context the server was loaded in (the default one in the service; an isolated one in the
   host tests). The await does not hold a thread-pool thread while a long request runs. The content root is given with a trailing separator,
   as `ApplicationPhysicalPath` was; the client address is `Connection.RemoteIpAddress`, an IPv4-mapped address as IPv4 (`UserHostAddress`).
6. 200 with the result as `text/plain; charset=utf-8`. An exception around `ProcessDto` (it answers every business error as a `DtoException`
   itself) gives 500 with its message.

**No execution timeout.** Kestrel and IIS in-process have none for a request (Web.config's `executionTimeout="3600"` has no counterpart);
the client waits up to an hour. Kestrel's data-rate minimums stay at their defaults.

**Built output** (`OpenPmsDentalServer\bin\Debug`, the lane's x64 build): 442 files, flat, no sub folder; `OpenPmsDentalServer.exe` and
`.dll` PE32+ 0x8664; `OpenPmsDentalServer.runtimeconfig.json` with `includedFrameworks` Microsoft.NETCore.App, Microsoft.WindowsDesktop.App
and Microsoft.AspNetCore.App 10.0.15, `System.Globalization.UseNls: true` and `System.GC.Server: true` (the Web SDK's default); the runtimes'
`coreclr.dll`, `hostfxr.dll`, `hostpolicy.dll`, Kestrel, WPF and Windows Forms beside it; `OpenPmsDentalBusiness.XmlSerializers.dll` from
the generator (S3b-3); `appsettings.json` and `web.config` copied. The folder is what a host runs: copy it whole (decision 20: the host
installs nothing for .NET; the IIS option needs only the ASP.NET Core Module of the .NET 10 Hosting Bundle, `OPT_NO_RUNTIME=1
OPT_NO_SHAREDFX=1`). A host runs a Windows Server version on Microsoft's .NET 10 list (decision 8).

## 2. The client: OpenDentalServerHttp

`OpenPmsDentalBusiness/WebServices/OpenDentalServerHttp.cs` (new) implements `IOpenDentalServer`: `ProcessRequest(dto)` POSTs the DTO as
`text/plain; charset=utf-8` to the address the user gave (`RemotingClient.ServerURI`) and returns the answer's body, the same strings the
SOAP envelope carried. One cached `HttpClient` for every address and thread, made again when the proxy settings change:
- the old proxy's settings: `Timeout` one hour; the proxy of `MiddleTierProxyConfig.xml` (`RemotingClient.MidTierProxyAddress`, with its user
  and password) or else the system's (`HttpClient.DefaultProxy`, as the SOAP proxy took `WebRequest.DefaultWebProxy`); the old User-Agent
  (`... MS Web Services Client Protocol 4.0.30319.296; IE8Mercury`, the firewall note kept);
- `SocketsHttpHandler` with `PooledConnectionLifetime` 15 minutes (a server that moves to another address is found);
- `SendAsync(...).GetAwaiter().GetResult()`: the calls stay synchronous, and the test server refuses the synchronous `Send`;
- an error status (413 included) is an `HttpRequestException` with the status code and the server's text in its message; no answer at all is
  HttpClient's own `HttpRequestException`; the timeout a `TaskCanceledException`.
- `HttpMessageHandlerOverride`, for tests only (null in the program): the handler every request goes through instead of the network.

`OpenDentalServerProxy.GetOpenDentalServerInstance()` returns the mock when a test set one, otherwise `new OpenDentalServerHttp(ServerURI)`;
its `#if NETFRAMEWORK` and `MiddleTierClientNotPortedMessage` (S3b-3) are gone. **The connection-lost retry** keeps its meaning:
`RemotingClient.SendAndReceiveRecursive` (lines 356-375 before) and `Meth.GetIsMiddleTierAvailable` (484-493) catch
`HttpRequestException` and take `HttpRequestError.ConnectionError` (`OpenDentalServerHttp.IsConnectionFailure`) where they took
`WebExceptionStatus.ConnectFailure`; a name that does not resolve, a proxy error, an error answer or a timeout is not retried, as before.

**Deleted:** `OpenPmsDentalServer/ServiceMain.asmx`, `ServiceMain.asmx.cs`, `Web.config` and the classic project file;
`OpenPmsDentalBusiness/WebServices/OpenDentalServerReal.cs`; `OpenPmsDentalBusiness/Web References/OpenDentalServer/*` (Reference.cs,
.map, .disco, .wsdl). `OpenPmsDentalBusiness.csproj` needed no item change (S3b-3 had removed the `WebReferenceUrl`); three of its comments
now say the Middle Tier's proxy went. The `SGenTypes` list (the DTO envelopes) stays: they are what the HTTP body carries. No SOAP
compatibility (plan, section 8 item 11): client and server switch together, and the version check refuses a mix anyway.
`Adjustment.TaxTransID` now travels (S3b-0 item 8; harmless, both ends are one build).

## 6. Running the host tests against a running server

`MIDDLETIER_TEST_URL` switches the suite from the in-process servers to a running server; `MIDDLETIER_TEST_DB` (default `s3b6_gate`, must
start with `s3b6_`) is the scratch database that server's config file names, which the run builds before its first request and drops
afterwards (`S3B6_KEEP_DB=1` keeps it); `MIDDLETIER_TEST_CERT_THUMBPRINT` is the SHA-1 thumbprint of a test certificate that Windows does not
trust. The tests that need the in-process servers (version mismatch, 413 at 1 MiB, the endpoint's HTTP and path answers) are
inconclusive then; the two users run on the one database. The server must not have served a request before the run (start or restart it
first), so its first request reads the new database.

## 7. The 3b gate's check of the Windows service, written for a person

**Automated (LAUNCH-3b):** `tools/Test-MiddleTierService.ps1` does steps 1 to 8 below in one elevated run for the owner, with the test
certificate as a PFX file instead of a store certificate, a free port, an `mtsvc_` scratch database and the service name
`OpenPmsDentalServer-Test`, and the client session of step 7 with `-ClientSession`; the command, what it changes and what to send back are
in [docs/launch-checks-3b.md](../launch-checks-3b.md), check 2. The steps below stay as the manual way.

On the build PC, in an elevated PowerShell where it says so; nothing here is needed by the office (O-7). Use the same commit for the server
and the tests (the version check of a Release server compares the two builds).

1. Build the server: `odbuild.ps1 -Root <worktree> -Projects OpenPmsDentalServer -ScopedRestore -Platform x64 -Configuration Release`
   (Debug works too and skips the version check). Copy `OpenPmsDentalServer\bin\Release\` whole to a test folder, for example
   `C:\MiddleTierGate\`.
2. Elevated: make a test certificate, `New-SelfSignedCertificate -DnsName localhost -CertStoreLocation Cert:\LocalMachine\My
   -NotAfter (Get-Date).AddDays(7)`, and note its thumbprint.
3. In `C:\MiddleTierGate\appsettings.json`: `Kestrel:Endpoints:Https:Url` `https://127.0.0.1:7443`, `Certificate:Subject` `localhost` and
   `AllowInvalid` `true` (a self-signed certificate is not trusted, and Kestrel's store lookup takes only valid ones otherwise).
4. In `C:\MiddleTierGate\OpenDentalServerConfig.xml` (copy the sample from `OpenPmsDentalServer\`): `ComputerName` 127.0.0.1, `Database`
   `s3b6_gate`, `User` root, `Password` empty, `ApplicationName` `/OpenDentalServer`.
5. Elevated: `sc.exe create OpenPmsDentalServer binPath= "C:\MiddleTierGate\OpenPmsDentalServer.exe" start= demand`, then
   `sc.exe start OpenPmsDentalServer`; `sc.exe query OpenPmsDentalServer` says RUNNING. (It runs as LocalSystem, which can read the
   certificate's key in `LocalMachine\My`. A start that fails writes its reason to the Application event log.)
6. Not elevated, in the worktree: build the tests (`odbuild.ps1 -Projects MiddleTierHostTests -ScopedRestore -Platform x64`), set
   `MIDDLETIER_TEST_URL=https://127.0.0.1:7443/OpenDentalServer/ServiceMain.asmx`, `MIDDLETIER_TEST_DB=s3b6_gate` and
   `MIDDLETIER_TEST_CERT_THUMBPRINT=<the thumbprint>`, and run `run-tests.ps1 -Root . -Mode Targeted -Platform x64 -Include
   MiddleTierHostTests`. Expected: 16 passed and 3 inconclusive (the in-process-only tests of section 6), NoHqTests as usual.
7. The client session (the gate's second part, once the program builds, S3b-4): trust the test certificate for the user (import it into
   Trusted Root), start the program, choose the Middle Tier address `https://127.0.0.1:7443/OpenDentalServer/ServiceMain.asmx`, log in as
   `s3b6usera` (its password is in `tests/MiddleTierHostTests/HostTestRun.cs`) while the database is kept (`S3B6_KEEP_DB=1` in step 6),
   open a patient and close the program.
8. Elevated: `sc.exe stop OpenPmsDentalServer`, `sc.exe delete OpenPmsDentalServer`, remove the certificate (and its Trusted Root copy),
   delete `C:\MiddleTierGate\`; drop `s3b6_gate` if it was kept.

The IIS option is not part of the gate (O-7); a future office server follows the plan's section 10 step 4 with `web.config`.
