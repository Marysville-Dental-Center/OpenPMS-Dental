## 1. The shape: one switch per layer, on settings that follow the target framework

`Directory.Build.props` sets `TargetFramework` to `net10.0-windows` (`ODTargetFramework`) for every SDK-style project that names none, and
names `Directory.Build.Net.props` as `BeforeMicrosoftNETSdkTargets`. Sdk.targets of Microsoft.NET.Sdk imports that file right after the
project's own properties and before every file of the SDK's targets (line 13 of `Sdk.targets` in SDK 10.0.115): the one point where a
setting can depend on the project's `TargetFramework`, `OutputType` and name and still be seen by everything the SDK computes from it (the
target framework and runtime identifier inference, the apphost, the output paths, the restore's targets and lock files, the runtime packs).
`Directory.Build.props` itself runs before the project's properties, where neither the target framework nor the output type is known, and
`Directory.Build.targets` runs after the SDK's runtime identifier inference, too late for `RuntimeIdentifier` and `SelfContained`.

Every setting of `Directory.Build.Net.props` applies only to a project whose `TargetFramework` is `net10.0-windows`. A project that still
names `net48` builds exactly as on `main` (x86, .NET Framework 4.8), and the evaluated table (section 3) shows it.

**Every project keeps its own `<TargetFramework>net48</TargetFramework>` line in this package.** The first commit removed the line from the 30
SDK-style projects outside `tests\`; the first lane build then showed why that cannot stand: `NoHqTests`, which every package's Targeted run
includes and which stays on .NET Framework with the x86 test runners until S3b-5, references CodeBase, DataConnectionBase and the business
library, and through it ODCrypt, OpenPmsDentalStorage, PasswordVaultWrapper and the PDFsharp source builds. A net48 project cannot
reference a net10.0 one (NU1004 in locked mode, NU1201 otherwise), so a retarget of every project at once leaves nothing of NoHqTests (or
any other test project) buildable. `74e9f9ca2` put the lines back. **A layer package retargets a project by deleting its net48 line** (and
adding what the project needs: `UseWindowsForms`/`UseWPF`, packages), bottom-up as the plan orders S3b-2, S3b-3 and S3b-4; the test projects
switch in S3b-5, when `tests\Directory.Build.props` loses its net48 line. What a project gets then is in the table of section 3, evaluated
now with `/p:TargetFramework=net10.0-windows`.
