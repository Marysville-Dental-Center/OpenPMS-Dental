# Port note: S3b-5 (the tests on .NET 10 x64)

Package S3b-5 of stage 3b of the .NET 10 move ([docs/specs/net10-plan.md](../specs/net10-plan.md): the S3b-5 row, section 7, the S3a-12
pointer-size tests, decisions 9, 14, 16 and 19-24), built on the shared settings of S3b-1 ([S3b-1.md](S3b-1.md), section 9), the layers of
S3b-2, S3b-3 and S3b-4 and the Middle Tier of S3b-6 (every handoff to S3b-5 in their notes, answered in section 8), and on the spike
([S3b-0.md](S3b-0.md), items 3, 7 and 11, "Consequences for S3b-5"). Branch `net10/s3b5-1` from `net10/switch` (`0ced90708`), 2026-11-16.
No schema change. No program with a window was started, no WPF picture test was run (the owner's desktop session is disconnected), scratch
databases only on 127.0.0.1:3306 (the suites' own prefixes, `s3b5_` where a suite takes one), all dropped. Decision 24 (number formatting)
is S3b-FMT's: the formatting differences the runs show are listed in section 9, not fixed.

Commits: the project files (`e289196fc`), the whole filter's build with the code pages (`df8c37fef`), the suites and the retired binding
checks (`b5116659b`), the TimeSpan fix and the remaining suites (`a4e9d9468`), the last suites (`bc769207d`), this note.

## 1. Summary

- **Every test project is `net10.0-windows` x64**, framework-dependent on the build PC's x64 runtime: `tests\Directory.Build.props` names no
  target framework any more, so all 115 test projects under `tests\` and the legacy `UnitTests` (with its `UI Testing` windows, kept) get
  the repository's; the 12 that were .NET 10 ahead of S3b-5 lost their own line. `tests\TopazStandIn` names net48 itself, on purpose (a
  stand-in for Topaz's .NET Framework control): the one .NET Framework project of the repository.
- **The whole filter restores and builds again**: the lane's full `OpenDental.Local.slnf` build with `-Platform x64` and **no
  `-ScopedRestore`** restores every project and builds with **0 errors** (no NU1201, no NU1004 any more). DocumentationBuilder builds (its
  build waited for UnitTests, S3b-4) and has its lock file.
- **Runs:** every test project but the WPF picture ones and the two the coordinator keeps (InitSqlTests, ForkMigrationTests), x64 with
  `-RequireBuildOutput`: 122 assemblies, 10,342 tests, 10,281 passed, 30 skipped, 31 failed at the last run of each, every failure explained
  in section 6 (S3b-FMT's number formatting, S3b-7's release files, one open .NET difference, one headless WPF picture). Against the last
  net48 Full run (`gate3a-full.txt`) every count that changed is explained in section 7.
- **Product fixes** for real .NET 10 behaviour differences, each the smallest change that keeps the .NET Framework's behaviour (section 5):
  TimeSpan.FromX rounding (the time card window and the appointment grid), CAPI keys opened through CNG (the connection settings tool, the
  Direct import), ODZip's path characters, the "any CPU, 32-bit preferred" rule of the native-first chooser, the helper's test module load,
  and the IIS site root of the Middle Tier server.

## 4. The helper and the probes

- **The helper runs from the program's output.** `Helper32Tests\Support\HelperCopy` (linked by BINBTests and now VendorDirectTests) makes
  one helper folder per test process, `helper32-copies\<pid>-<hex>\` beside the test, of hard links to every file of
  `OpenPmsDental\bin\<configuration>\Helper32\` (the self-contained x86 helper with its own runtime, S3b-4), and each copy is the apphost
  under its own name there. The test assembly whose test module the helper loads is x64 like every test assembly, which an x86 process
  cannot load: the folder gets an any-CPU copy of it (Mono.Cecil). The helper's `TestModule` now loads that file by path (product fix: the
  .NET default context knows only the helper's `.deps.json`). `ProgramEndTests` starts its probes from the test's own folder (TestProbeHost
  is x64 and cannot start beside the helper's x86 runtime).
- **TestProbeHost** (S3b-6's handoff): `ProbeProcess.CopyHost` also copies `TestProbeHost.dll`, `.runtimeconfig.json` and `.deps.json` into a
  folder other than its own (VendorDirectTests' SSH.NET probe; ReleaseFlowTests' Helix probe is S3b-7's); a caller's config text only lands
  as a file (no binding redirects on .NET).
- **The pointer-size columns** stay: Topaz in the program's process is the x64 column with an any-CPU stand-in (BINBTests, Helper32Tests'
  module tests; an x86-only one goes to the helper, TopazWrapperTests), and the helper tests run the x86 helper against the x64 test
  process. NativeFirstTests pins the .NET rule for "any CPU, 32-bit preferred" (section 5).
- **Tests that start a program or tool** start it from its own output folder: AdoptionValidation.Tests' runbook dry run (from
  `tools\AdoptionValidation\bin\<configuration>\`; S3b-3's handoff), the EHR stylesheet child (`EhrStylesheetStarter.FolderChildForTests`,

## 9. Open, and for the lead

- **S3b-FMT (decision 24), the formatting differences the runs show:** GoldenOutputTests' six (section 6) and BINBTests'
  `Fixture_G15AndG7Texts`. Not changed.
- **S3b-5W (the WPF picture baselines, gallery G5):** ToothChartImageTests (263 on net48, of them the picture tests that compare the
  `Baselines\wpf-net48` images), ToothChartHostTests (20), WindowChecksTests (32: its in-process checks drive the program's windows), and
  BINATests' `WpfChart_StartsOnAHiddenForm`. All three projects build on .NET 10 x64 (ProgramDriver patches the entry assembly with
  `Assembly.SetEntryAssembly`, as .NET has no AppDomainManager).
- **The ZIP entry that inflates past its claimed size (EhrTests): accepted, pinned (lead, 2026-11-16).** On .NET the importer cannot see
  past the claim (ZipArchiveEntry's stream stops at the size the header claims), so the refusal reads "The file could not be read:
  Unexpected end of file has occurred. ... Line 1, position 1001." instead of "larger, uncompressed, than the importer reads". Same outcome:
  refused, no codes, nothing past the claimed 1,000 bytes read. `Zip_AnEntryThatInflatesPastThePartLimit_...` pins the .NET 10 text for the
  understated entry ("could not be read", "Line 1, position 1001") and keeps the net48 asserts for the honest one.
- **DateTime.AddHours/AddMinutes/AddSeconds with a fractional value** no longer round to the millisecond either (the same .NET change as
  TimeSpan.FromX; UnitTests' time card tests built their clock times that way and now build them with `ODTimeSpan`). The product's own
  calls with fractional values were not swept here (their argument types are not visible to a text scan, and whole numbers are exact).
  **Assigned to S3b-FMT** (lead, 2026-11-16): decision 24 of the plan names the sweep (AddHours/AddMinutes/AddSeconds/AddMilliseconds with
