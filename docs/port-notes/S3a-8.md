# Port note: S3a-8 (tests that use .NET Framework-only APIs)

Package S3a-8 of stage 3a, wave 1, of the .NET 10 move ([docs/specs/net10-plan.md](../specs/net10-plan.md), the S3a-8 row and the Known
overlaps paragraph; section 3; https://learn.microsoft.com/en-us/dotnet/core/porting/net-framework-tech-unavailable): branch `net10/s3a8-1`
from `main` (`c01ea6fe4`). The tests of the row no longer call what .NET does not have: reflection-only loads, new application domains,
`AppDomain.DefineDynamicAssembly`, `Assembly.GlobalAssemblyCache` and `Marshal.GetComSlotForMethodInfo`, and the two tests that load the
program read its managed assembly through one helper. Test code only: no program code, no schema change, no new package (Mono.Cecil 0.10.3
is the version of `Directory.Packages.props` that LibraryBindingTests already used; four more test projects reference it), nothing
downloaded, no program started. The binding-redirect tests stay until 3b, as the plan says.

Commits: `dac3fcc36` (the new project `tests/TestProbeHost` in `OpenDental.sln` and `OpenDental.Local.slnf`, for the lead to review, since the
plan names `OpenDental.sln` the lead's), `e51487dd5` (its lock file's `win-x86` target), `ccf6ae704` (the tests), and this note with the plan's
status line.

## 2. The child process: TestProbeHost

.NET cannot create an AppDomain, so the three probes that need their own static state, config or application base run in a process of their
own. The test assembly is a library and cannot be started, and the .NET Framework's run-time C# compiler (used by ToothChartImageTests'
`SecondProcess`) is not on .NET either, so a small exe project does it: `tests/TestProbeHost` (net48, x86, no package; the three MSTest
packages that `tests/Directory.Build.props` gives every project under `tests/` are removed in its project file). Its name does not end with
`Tests`, so the test runner never runs it and `Directory.Build.targets` gives it no shared test config. It is in `OpenDental.sln` and
`OpenDental.Local.slnf` because the lane builds single projects as solution targets; LibSpellTests, PdfLibraryTests and VendorDirectTests
reference it, so `TestProbeHost.exe` lands next to their assemblies.

- `ProbeProcess.Start(folderBase,configText,typeHandler,timeout)` copies `TestProbeHost.exe` into `folderBase` as `TestProbeHost-<12 hex>.exe`
  (so `folderBase` is its application base and `<that>.exe.config`, written from `configText`, its config alone), starts it with no window and
  redirected streams, and waits for its `ready` line. `Call(command,args)` sends one line and returns the handler's result, or throws with the
  handler's exception text, the child's exit code or a timeout (the child is then ended). `Dispose` closes the child's standard input, which
  ends it, waits up to 10 seconds (then ends it) and deletes the copy and its config.
- `TestProbeHost.exe <assembly> <type>` loads the handler's assembly (by name when it is in its own folder, so a config or type string that
  names it finds the same copy; from its file otherwise) and calls `public static string Handle(string command,string[] args)` for each line,
  on its MTA main thread, as a test method runs on the runner's. Standard output carries only the replies; the console output of the work goes
  to standard error, which the test keeps for its messages.
- `ProbeText`: every field is UTF-8 in base64, so a line is ASCII and no field breaks it; lists carry their count first.

## 3. The program's managed assembly: ProgramAssembly

`tests/ProjectFileTests/ProgramAssembly.cs`, linked like `BuildOutput.cs` (NoHqTests and ReleaseFlowTests link it; ProjectFileTests compiles
it with its folder): `Find(folder,name)` gives `name.dll` when it is there, else `name.exe`, else null; `GetPath` ends the test through
`BuildOutput.NotBuilt` when neither is built and fails when the file found holds no managed code ("a native apphost?", with `name.dll` missing);
`Load` is `Assembly.LoadFrom(GetPath(...))`. On .NET Framework nothing changes (there is no `OpenPmsDental.dll`); on .NET the `.exe` is the
apphost and the `.dll` is the program. S3a-7 applies it at `tests/ReleaseFlowTests/ProgramNamesTests.cs:191`
(`ProgramAssembly.Load(folder,"OpenPmsDentalHL7")`): ReleaseFlowTests already compiles it. Its own tests are
`tests/ReleaseFlowTests/ProgramAssemblyTests.cs` (scratch folders in the temp folder: a native `cmd.exe` copy as the apphost and a copy of
`CodeBase.dll` as the managed file).
